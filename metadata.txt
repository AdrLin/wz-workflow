    Features:
    • 14-step automated workflow for building permit analysis
    • Deep-learning (CNN) roof-shape classification
    • Random Forest classification of biologically active surface (PBC) from LiDAR
    • LiDAR point cloud processing, robust on very large clouds
    • Cadastral data integration (ULDK/BDOT)
    • Automated Word report generation
    • Urban planning indicators (WPZ, WIZ, WPBC)

    ML models (~218 MB) are downloaded automatically on first use from GitHub Releases.

    Kompleksowe narzędzie do automatycznej analizy warunków zabudowy w Polsce.
    Automatyzuje 14-stopniowy proces analizy urbanistycznej z wykorzystaniem uczenia maszynowego
    (klasyfikacja kształtu dachów siecią CNN, klasyfikacja powierzchni biologicznie czynnej
    lasem losowym na podstawie danych LiDAR).
    Modele ML (~218 MB) są pobierane automatycznie przy pierwszym uruchomieniu z GitHub Releases.

    NOWE FUNKCJE
    - Obsluga planu ogolnego (APP 2.0): nowy modul odczytuje strefe planistyczna,
      obszar uzupelnienia zabudowy (OUZ) i obszar zabudowy srodmiejskiej z warstw
      planu, przecinajac je z granica terenu inwestycji (krok 13). Przy dzialce w
      kilku strefach wybierana jest strefa o najwiekszym udziale powierzchniowym.
      Dopasowanie warstw jest odporne na zmiane nazw. Nowe zmienne pog_* trafiaja
      do szablonow Worda (krok 14); stare szablony dzialaja bez zmian dla spraw
      wszczetych przed uchwaleniem planu.
    - Narzedzia liczace z zaznaczenia na mapie: srednia wysokosc zabudowy oraz
      inne parametry liczone wprost z zaznaczonych dzialek/budynkow.
    - Parametry budynkow prezentowane jako listy wartosci zamiast usrednien.

    POPRAWKI FUNKCJONALNE
    - Pole sredniej wysokosci jest teraz dostepne zawsze (wczesniej aktywne tylko
      przy wariancie z paragrafu 7 ust. 3).
    - Okno bledu importu pokazuje prawdziwa przyczyne zamiast ogolnego komunikatu.
    - Naprawiono blad formatowania wskaznikow WPZ/WPBC w oknie danych dzialki
      (pola tekstowe z "%" powodowaly wyjatek przy formacie liczbowym).

    ZGODNOSC Z QGIS 4 (Qt6) — przy zachowaniu pelnej zgodnosci z QGIS 3
    - qgisMaximumVersion podniesiony do 4.99, aby wtyczka ladowala sie w QGIS 4.
    - Importy PyQt ida przez warstwe zgodnosci qgis.PyQt.
    - Wszystkie enumy Qt i QGIS w pelnej, kwalifikowanej formie (wymagane przez
      PyQt6, poprawne takze w PyQt5); QDialogButtonBox przez StandardButton.
    - QAction importowany z QtGui w Qt6, z QtWidgets w Qt5.
    - Nowy modul qt_compat przywraca stale typow pol QVariant usuniete w Qt6,
      jako wartosci liczbowe zgodne z PyQt5 (poprawny zapis pol double/int).
    - Poziomy paska komunikatow przez Qgis.MessageLevel zamiast liczb.
    - Sprawdzanie typu warstwy przez isinstance() zamiast porownania z liczba.
    - sip importowany odpornie (samodzielny modul sip nie istnieje w Qt6).
    - exec_() zastapione przez exec().
    - pdal:filter przekazuje wymagany w QGIS 4 parametr VPC_OUTPUT_FORMAT
      (ustawiany tylko gdy algorytm go ma, wiec QGIS 3 dziala bez zmian);
      format posredni chmury wykrywany automatycznie z wejscia (LAS/LAZ/COPC).
    - Wartosci parametrow budynkow rzutowane na natywne typy Pythona przed
      zapisem (typy numpy byly odrzucane przez QGIS 4 jako PyQt_PyObject).
    - Ciezkie biblioteki (pandas, numpy, scipy, scikit-learn) importowane leniwie:
      wtyczka wstaje nawet bez nich i zglasza czytelny komunikat dopiero w kroku,
      ktory ich wymaga.
    - Windows: klasyfikator dachow uruchamiany prawdziwym interpreterem Pythona
      zamiast qgis-bin.exe (ktory otwieral druga kopie QGIS i zawieszal workflow);
      petla oczekiwania na wynik nie zawiesza juz GUI i konczy sie po limicie czasu.
